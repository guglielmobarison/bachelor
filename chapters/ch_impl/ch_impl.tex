\section{Generazione configurazioni di pseudo-settori collassati}
La generazione delle configurazioni collassate segue l'algoritmo descritto nella Sezione~\ref{subsec:algo-collassati}.
Il processo inizia con il caricamento dei dati dei settori elementari. La funzione \texttt{load\_fir\_data} legge il dataset delle \gls{fir} da un file CSV compresso.
\begin{lstlisting}[language=Python, caption={}]
def load_fir_data() -> gpd.GeoDataFrame:
    df = pd.read_csv(DEFAULT_FIR_FILE, sep=",", compression="gzip",
                     quotechar='"', skipinitialspace=True)

    for fir_id, group in df.groupby("Airspace ID"):

Questa fase preparatoria garantisce la corretta formazione dei poligoni spaziali, ordinando i vertici secondo la sequenza logica, chiudendo le geometrie incomplete e convertendo le coordinate in un sistema di riferimento appropriato per le operazioni spaziali successive. Ogni pseudo-settore elementare viene memorizzato con i suoi intervalli di quota minimo e massimo, attributi fondamentali per la fase successiva.
La verifica della sovrapposizione verticale tra settori adiacenti è implementata da una funzione dedicata che applica il criterio matematico descritto nell'algoritmo. La funzione \texttt{vertical\_overlap} calcola l'intersezione tra gli intervalli di quota di due settori, considerandoli compatibili solo quando la sovrapposizione supera una soglia minima configurata.
\clearpage
\begin{lstlisting}[language=Python, caption={}]
def vertical_overlap(row1: pd.Series, row2: pd.Series) -> bool:
    min1, max1 = row1["Min Flight Level"], row1["Max Flight Level"]
    min2, max2 = row2["Min Flight Level"], row2["Max Flight Level"]
    overlap = min(max1, max2) - max(min1, min2)
    return overlap >= VERTICAL_OVERLAP_MARGIN  
\end{lstlisting}
L'algoritmo esplora ricorsivamente lo spazio dei settori partendo da un elemento non visitato, espandendosi verso i vicini spazialmente adiacenti e verticalmente compatibili. La probabilità di inclusione $p(|G|)$ diminuisce linearmente con la dimensione del gruppo corrente, favorendo la formazione di aggregati di dimensioni moderate. Ogni gruppo completato viene fuso in un'unica geometria poligonale attraverso un'operazione di unione spaziale, producendo infine un GeoDataFrame contenente tutte le configurazioni collassate con i relativi metadati identificativi.
\begin{lstlisting}[language=Python, caption={}]
def generate(self) -> gpd.GeoDataFrame:
    merged_indices = set() 
    merged_records = []
    sindex = self.sectors.sindex  # Indice spaziale per ricerca efficiente
    
    for idx, row in self.sectors.iterrows():  
        if idx in merged_indices: continue              
        collapsed_sector = {idx}  
        stack = [idx]             
        
        # Espansione ricorsiva del gruppo
        while stack and len(collapsed_sector) < self.max_size:
            current_idx = stack.pop()  # Estrazione settore corrente dallo stack
            
            # Ricerca vicini spaziali tramite indice spaziale
            possible_idxs = list(sindex.query(
                self.sectors.loc[current_idx, "geometry"], 
                predicate="touches"
            ))
            
            # Valutazione dei vicini candidati
            for neighbor in possible_idxs:  
                if neighbor in merged_indices: continue  
                                    
                if not self.vertical_overlap(
                    self.sectors.loc[current_idx],
                    self.sectors.loc[neighbor]
                ): continue
                
                group_size = len(collapsed_sector)
                p_merge = (self.max_size - group_size + 1) / \
                          (self.max_size + 1)
                
                # Decisione probabilistica di inclusione
                if npr.rand() < p_merge:  
                    collapsed_sector.add(neighbor)  
                    stack.append(neighbor)         
                    if len(collapsed_sector) >= self.max_size: 
                        break  
        
        # Unione geometrica dei settori del gruppo
        merged_geom = unary_union([
            self.sectors.loc[i, "geometry"].buffer(0) 
            for i in collapsed_sector
        ])
        
        merged_records.append({
            "elementary_sector": list(collapsed_sector),
            "geometry": merged_geom,
            "collapsed_sector": generate_id()  # Generazione ID univoco
        })
        merged_indices.update(collapsed_sector)  
            
    return gpd.GeoDataFrame(merged_records, crs=self.sectors.crs)
\end{lstlisting}

\subsection{\gls{dac}}
L'implementazione operativa del problema del \gls{dac} è stata realizzata in \gls{python}, sfruttando la libreria \texttt{DOcplex} per la modellazione e la risoluzione di problemi di programmazione lineare intera. Il prototipo segue fedelmente la formulazione matematica illustrata in Sezione \ref{sec:dac_math}, traducendo le variabili decisionali, i vincoli di permanenza, quiescenza e compatibilità tra configurazioni in vincoli \gls{cplex}

I dati operativi vengono caricati da file JSON organizzati per configurazione, comprendenti la domanda di traffico prevista, le capacità nominali dei pseudo-settori collassati e le configurazioni ammissibili. La funzione \texttt{load\_data\_for\_config} gestisce il caricamento dei dati, restituendo oggetti \gls{python} direttamente utilizzabili per costruire il modello.
\begin{lstlisting}[language=Python, caption={}]
tr, c, dizio_conf = load_data_for_config(config_id, data_dir)
\end{lstlisting}
L'eccesso di domanda rispetto alla capacità dei settori viene calcolato con la funzione \texttt{compute\_excess}, che restituisce per ogni settore e intervallo temporale il valore \(\max(\text{traffico} - \text{capacità}, 0)\):

\begin{lstlisting}[language=Python, caption={}]
def compute_excess(tr, c, T):
    excess = {}
    for s in tr:
        excess[s] = [max(tr[s][t] - c[s], 0) for t in T]
    return excess
\end{lstlisting}
Successivamente, \texttt{compute\_coefficients} aggrega l’eccesso a livello di configurazione, calcolando per ciascun intervallo temporale la somma degli eccessi dei settori appartenenti a quella configurazione.
\begin{lstlisting}[language=Python, caption={}]
def compute_coefficients(dizio_conf, excess, T):
    e = {}
    for conf, sectors in dizio_conf.items():
        e[conf] = {t: sum(excess[s][t] for s in sectors) for t in T}
    return e
\end{lstlisting}
La creazione delle variabili decisionali binarie \(x^c_t\) e ausiliarie \(s^c_t\) è gestita da \\\texttt{create\_decision\_variables}:
\begin{lstlisting}[language=Python, caption={}]
def create_decision_variables(model, X, dom):
    if dom == 'cont':
        x = model.continuous_var_dict(keys=X, name='x', lb=0, ub=1)
        s = model.continuous_var_dict(keys=X, name='s', lb=0, ub=1)
    elif dom == 'bin':
        x = model.binary_var_dict(keys=X, name='x')
        s = model.binary_var_dict(keys=X, name='s')
    else:
        raise ValueError("Dominio non valido. Usare 'cont' o 'bin'.")
    return x, s
\end{lstlisting}
I vincoli principali del modello vengono aggiunti con la funzione \texttt{add\_constraints}, che implementa:
\begin{itemize}
    \item l'unicità di una configurazione attiva per ogni intervallo
    \item la compatibilità tra configurazioni consecutive
    \item le transizioni tra intervalli temporali
    \item i vincoli di permanenza e quiescenza
\end{itemize}
\begin{lstlisting}[language=Python, caption={}]
def add_constraints(model, x, s, CONF_t, CONF_tc, T, tp, tq):
    # Vincolo: assegnazione di una configurazione per ogni istante
    for t in T:
        model.add_constraint(
            model.sum(x[(t, c)] for c in CONF_t[t]) == 1
        )

    # Vincolo: transizione tra configurazioni
    for t in T[:-1]:
        for c in CONF_t[t]:
            model.add_constraint(
                x[(t, c)] - model.sum(x[(t + 1, k)] for k in CONF_tc[(t + 1, c)]) <= 0
            )

    # Vincolo: cambiamento tra istanti consecutivi
    for t in T[1:]:
        for c in CONF_t[t]:
            if c in CONF_t[t - 1]:
                model.add_constraint(x[(t, c)] - x[(t - 1, c)] <= s[(t, c)])
            else:
                model.add_constraint(x[(t, c)] <= s[(t, c)])

    # Vincolo di permanenza
    if tp >= 2:
        for t in T:
            model.add_constraint(
                model.sum(
                    s[(w, c)] for w in range(t, min(t + tp, len(T))) 
                    for c in CONF_t[w]
                ) <= 1
            )

    # Vincolo di quiescenza
    if tq >= 2:
        for t in T:
            for c in CONF_t[t]:
                model.add_constraint(
                    x[(t, c)] + model.sum(
                        s[(w, c)] 
                        for w in range(t + 1, min(t + tq + 1, len(T))) 
                        if c in CONF_t[w]
                    ) <= 1)
\end{lstlisting}

La soluzione ottimale viene ottenuta tramite \texttt{model.solve()} e salvata in formato JSON.
